# Spec Delta

## Purpose

建立真实且可验证的个人书库，让上传文件、元数据和按需资源之间有明确边界；长期保存的原件始终能以原扩展名和原字节核验，解析、缩略图及缓存任务失败或重建时都不会损坏书籍和阅读状态。

## ADDED Requirements

### Requirement: 原格式只读保存
系统 MUST 保留上传原件的原始扩展名、字节、大小和内容哈希，读取与派生处理不修改原件；不支持格式也不得偷偷转换。阶段 2；来源 31–38、219–236 行。

#### Scenario: 上传与派生重建
- **WHEN** 上传 EPUB/PDF/CBZ/CBR 后提取封面、章节或页面并清理派生缓存
- **THEN** 原件 SHA-256 与大小始终与上传文件一致，进度不被删除，派生内容可重新生成。

### Requirement: 单个批量与可恢复上传
系统 SHALL 支持选择文件、拖拽、手机文件入口和批量上传，显示每项进度、失败重试与重复提示；对损坏、加密、超限和不支持格式提供明确结果。阶段 2；来源 90、191–195、401–405、436 行。

#### Scenario: 上传中断与重复
- **WHEN** 一个批次部分失败或再次上传相同文件
- **THEN** 成功项保持可用、失败项可单独重试、重复文件有明确提示，不产生看似成功但缺原件的记录。

### Requirement: 真实可查询书库
系统 SHALL 用实际已保存的书籍提供搜索、格式/阅读状态筛选、排序、网格/列表、详情、继续阅读和最近添加；详情不强制下载全书，封面采用受限缩略图。阶段 2；来源 181–195 行。

#### Scenario: 大书库导航
- **WHEN** 用户在 1000–3000 本书中筛选并进入详情后返回
- **THEN** 采用分页或虚拟化保持滚动流畅、恢复筛选与位置，不挂载全库卡片和原始封面。

### Requirement: 有界异步索引
系统 SHALL 将元数据、目录、缩略图和归档解析作为有并发/超时限制的后台任务，任务状态与错误可观察；空闲时不持续耗尽 CPU。阶段 2、6；来源 68–73、234–236、437 行。

#### Scenario: 解析失败
- **WHEN** 解析任务异常退出、超时或发现不可信归档
- **THEN** 原件仍受保护，书籍状态显示具体失败与恢复入口，工作队列不被单个坏文件永久阻塞。
