# Spec Delta

## Purpose

让 iRead 能以单容器自托管并作为手机主屏幕应用使用，部署、升级、数据保存与缓存职责保持透明；应用壳在离线时仍可打开，更新不打断阅读，任何测试和设备支持声明都必须来自实际可复现的验证结果。

## ADDED Requirements

### Requirement: 可安装应用壳
系统 SHALL 提供 iRead manifest、192/512及maskable图标、theme/background色、standalone、启动URL与iOS/Android手动安装说明，离线只承诺已缓存 Shell 和有限资源。阶段 1 基础、阶段 5 深验；来源 368–376 行。

#### Scenario: 在线首访后离线打开
- **WHEN** Shell 缓存完成后离线重新打开已访问应用
- **THEN** 导航与本地外观可用，未下载内容明确不可用；不得宣称任意未缓存图书可离线阅读。

### Requirement: 缓存边界与可选更新
系统 MUST 排除原件、API 和带 Range 请求的通用 SW 缓存；更新只提示，由用户安全应用，阅读中不得自动刷新。阶段 1 基础、阶段 5 深验；来源 372–377 行。

#### Scenario: 阅读中有新版本
- **WHEN** 新 SW 等待激活且用户正在阅读
- **THEN** 保留当前页面并提示退出后更新；原件请求及206语义不被Shell fallback或CacheFirst改写。

### Requirement: 单容器与持久路径
系统 SHALL 通过多阶段构建由 Go 同源提供静态/API/资源，分离可配置的图书、SQLite和派生缓存路径，提供健康检查、环境样例、默认端口、日志/升级/备份说明。阶段 1 基础、阶段 2–6 数据闭环；来源 68–73、432–440 行。

#### Scenario: 容器重建
- **WHEN** 容器以相同持久卷重新创建
- **THEN** 已实现外观/数据库状态保留；完整产品还须验证原件/进度保留，生产镜像不常驻开发工具链。

### Requirement: 设置页缓存管理闭环
系统 SHALL 在设置页显示有限阅读缓存用量并提供清理操作，清理后反馈结果、更新用量，明确区分阅读缓存和原始图书。阶段 5–6；来源 234、377 行。

#### Scenario: 查看清理并重新阅读
- **WHEN** 用户查看缓存用量后清理阅读缓存，再重新打开书籍
- **THEN** 用量反馈已更新，原件、进度和偏好全部保留，必要派生资源可以重建；失败有原因和重试入口。

### Requirement: 不伪报平台验收
系统 MUST 区分桌面/移动模拟、真实iPhone Safari/主屏幕PWA及Android Chrome/PWA验证；iOS后台暂停不能被描述为持续后台下载。阶段 1 与后续各阶段；来源 216–217、397–430、478 行。

#### Scenario: 设备或容器环境受限
- **WHEN** 真实手机、大书样本或Docker构建环境不可用
- **THEN** 交付列明未执行项、原因、替代检查、剩余风险和可操作人工清单，不声称完整产品或真实设备已通过。
